# Cqlib-QML v0.1.0-beta.3

Beta 3 adds native PyTorch quantum layers and symbolic Angle/ZZ encoding for end-to-end hybrid training. It also improves sklearn estimator validation and serialization, and fixes BCE training and stale execution state.

These notes cover changes since `v0.1.0-beta.2`.

## New Features

### Native PyTorch Quantum Layers

- Added `from cqlib_qml.torch import QuantumLayer`, a standard `torch.nn.Module` with quantum weights registered as an `nn.Parameter`.
- Input and quantum weight gradients propagate through `loss.backward()`, allowing preceding and following classical layers to train with the same Torch optimizer.
- Supports CPU float32/float64, single samples, and multidimensional batches with features on the last axis. Inputs shaped `(..., inputs)` produce outputs shaped `(..., outputs)`.
- Reuses adjoint and parameter-shift differentiation for expectation-value outputs. Each forward call owns its execution state and Jacobians, so shared-layer calls can be combined in one backward pass.
- Supports Torch DataLoader, gradient accumulation, parameter freezing, `no_grad()`, and `inference_mode()`. `eval()` keeps Torch's normal behavior and does not disable differentiation.
- Added structure-validated `state_dict()` restoration. Save optimizer state separately through Torch's optimizer interface.

### Symbolic Angle and ZZ Encoding

- Added `encoder.to_ansatz(ansatz, *, num_features, input_prefix="x")` to `AngleEncoder` and `ZZFeatureEncoder`. Users can preserve input gradients without manually constructing encoding symbols.
- Supports Angle classical/dense modes and ZZ linear/full/circular entanglement with repeated layers. Encoding formulas and gate order match the existing numerical encoders.
- Generated input roles follow numeric feature order, including feature counts above ten. Repeated ZZ symbols contribute gradients from all their gate occurrences.
- Returns an independent base `Ansatz`, preserving circuit content, weight order, complete or partial assigned weights, measurement, differentiation configuration, and RNG state. Composition does not initialize missing weights or consume the source RNG.
- Source qubit IDs must be a permutation of `0..Q-1`; source qubit positions map to canonical IDs in the returned object. Sparse IDs are rejected at this entry point.
- Existing numerical `encoder(data)` behavior is unchanged, including repetition validation being limited to the new ZZ entry point.

## Fixes

### sklearn Estimators

- VQC rejects continuous regression targets before replacing fitted state.
- QSVM records `n_features_in_` and checks raw feature counts before prediction, probability prediction, and decision-function evaluation. Resetting or changing parameters clears fitted metadata.
- Fitted QSVM models own their encoder state, so later changes to the construction encoder do not alter predictions.
- Added native quantum-object serialization support for estimator pickling, joblib restoration, and process-based cross-validation. Serialization preserves shared object references, custom Ansatz state, and circuit qubit IDs.
- QSVM serialization discards caches in the serialized copy while preserving the live model's cache; restored caches are rebuilt on demand.

### Training and Numerical State

- Fixed QNN classification helpers using BCE with signed labels and expectation values. BCE now receives labels in `{0, 1}` and probabilities `(1 - expectation) / 2`, with the corresponding `-0.5` chain-rule factor during training.
- Reinitializing `Linear` parameters clears gradients and forward caches. Changing its activation invalidates the previous execution cache.
- Replacing a native DataLoader dataset resets its iteration-start state as well as its cursor and permutation.
- Ansatz execution and parameter-shift differentiation reject nonfinite initial state amplitudes.

## Compatibility and Usage

- Existing QNN, HQNN, VQC, and QSVM entry points remain available. Torch integration uses a separate module and optimizer lifecycle.
- `to_ansatz()` preserves partial weight assignments. Native `Ansatz.forward()` initializes only missing weights; `QuantumLayer` inherits weights only when the complete vector is assigned, otherwise it initializes the entire vector with Torch. Pass a complete `initial_weights` vector to retain selected existing values.
- Native Ansatz single-sample outputs retain shape `(1, out_dim)`; Torch single-sample outputs have shape `(out_dim,)`.
- Native checkpoint format remains `format_version=1`. Torch state dictionaries use their own interface and are not interchangeable with native checkpoints.
- Native restoration of nonempty partial weight dictionaries still requires completing the weights first. Torch restoration checks actual circuit structure, parameter roles, measurement, and differentiation configuration; it does not identify encoder configurations that generate identical circuits.

See the [Torch tutorial](https://github.com/cq-lib/cqlib-qml/blob/v0.1.0-beta.3/docs/tutorials/torch.md), [symbolic encoding guide](https://github.com/cq-lib/cqlib-qml/blob/v0.1.0-beta.3/docs/tutorials/encoder.md), and [hybrid training example](https://github.com/cq-lib/cqlib-qml/blob/v0.1.0-beta.3/examples/torch_hybrid.py).

## Documentation and Validation

- Added runnable hybrid training workflows using manual, Angle, or ZZ encoding, with DataLoader, Adam, loss-decrease checks, and model/optimizer restoration followed by the same update.
- Added closed-form and independent matrix-algebra references, input/weight and complete-network gradcheck, float32/float64 and multidimensional batch checks, gate-order assertions, and success/failure state-isolation regressions.
- Expanded sklearn coverage for estimator state, serialization, and process-based cross-validation.
- Local source validation passed all **1,202 tests** on macOS with Python 3.14 and cqlib 2.0.0b3. Ruff correctness checks and whitespace checks passed.
- Installed-wheel and sdist-rebuilt-wheel validation of the feature changes each passed **1,196 tests** and smoke checks; six source-only example tests run in the source suite. These local checks reused installed dependencies and do not replace cross-platform and multi-Python CI validation.

## Installation

Requirements remain **Python 3.11 or later** and **cqlib 2.0.0b3 or later**. PyTorch requirements are unchanged.

Once published on PyPI, install this beta version with:

```bash
python -m pip install "cqlib-qml==0.1.0b3"
```

The release tag is `v0.1.0-beta.3`; the package version `0.1.0-beta.3` is normalized to `0.1.0b3` under PEP 440.

## Beta Status and Known Limitations

- APIs and checkpoint formats may change in subsequent beta releases.
- Torch quantum execution supports CPU expectation values and first-order gradients. GPU execution, mixed precision/autocast, higher-order gradients, `torch.compile`, and `torch.func` differentiation/batching transforms such as `jacrev` and `vmap` are not supported.
- Each recorded forward call saves Jacobians, whose memory grows with samples, outputs, and parameters. Quantum statevector simulation also grows exponentially with qubit count.
- Symbolic encoder integration covers Angle and ZZ only. Amplitude, basis, and image encoders do not gain input-gradient support from this release. Dense phase gradients depend on the following circuit and measurement being sensitive to that phase.
- Hardware training executors, shots, and probability outputs for QuantumLayer are not available.
- Exact Torch training resume additionally requires the caller to preserve random state and data order. Native exact-resume requirements from beta 2 still apply.
- The cqlib 2.0.0b3 parameter-expression differentiation limitation at extreme parameter scales remains.
